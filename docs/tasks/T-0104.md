# T-0104 — Pinning: refs → SHAs, merge-base, drift

Milestone: M1 · Estimate: 1.5 d · Owner: A · Provisional: no

## Goal
The single function that turns user-supplied refs into immutable SHAs plus everything downstream
needs (merge-base, drift, order input), with the refusals that prevent nonsense inputs.

## Dependencies
T-0101, T-0102, T-0103. ADR-0005, `INT-102`/`INT-103`/`INT-104`/`INT-205`.

## Allowed file scope
- `internal/engine/pin.go` (and `pin_test.go`)
- `internal/model/pinned.go`

**May not touch:** `internal/gitx` internals (use its API), `internal/verify`.

## Implementation outline
1. `Pin(ctx, spec) (Pinned, error)`:
   - optional `fetch` (skipped with `--offline`, recorded as `stale_base_accepted`);
   - resolve base ref → SHA; resolve each source ref → SHA, or accept a 40-hex SHA directly;
   - refuse `HEAD`, `@{...}`, paths, and refs under `.ilvuno/` / `refs/ilvuno/`;
   - `merge-base(base, source)`; refuse if absent (`no_merge_base`, likely shallow/unrelated);
   - `rev-list --left-right --count` for ahead/behind; `drift = behind`;
   - refuse duplicates, refuse `source == base`, refuse self-source.
2. Order: sort by (base commit time, declared order, SHA) — total, reproducible.
3. Record per source: `{ref, sha, commit_time, merge_base_sha, ahead, behind}` and the resolved
   `base_ref` → `base_sha`.
4. `--strict-refs` re-resolve at the end and error `source_moved` if any differ.
5. Never return a ref downstream: the return type contains SHAs only.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | A ref that moves between two calls yields the same pinned SHA (asserted with a fixture that commits between calls) |
| AC-2 | `HEAD`, `@{u}`, `./path`, `refs/ilvuno/...` are refused with distinct codes |
| AC-3 | Missing merge-base yields `no_merge_base` with the `--unshallow` hint |
| AC-4 | Duplicate SHAs are refused with both refs named |
| AC-5 | Order is identical across 10 randomized input permutations |
| AC-6 | `--offline` records `stale_base_accepted` in the result and does not call fetch |
| AC-7 | The returned struct has no `ref` field consumed by later stages (compile-time: they take `sha`) |

## Test commands
```
go test ./internal/engine/ -run TestPin -count=1 -v
```

## Evidence requirements
Table of refusals with codes; the 10-permutation ordering log; one trace showing ref→SHA.

## Review checklist
- Is there any code path that re-resolves a ref after pinning?
- Does `--offline` ever proceed without recording that it used a possibly stale base?
- Is drift computed against the *merge-base*, not the source's own history?
