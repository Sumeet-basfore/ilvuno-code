# T-0002 — Deterministic fixture forge

Milestone: M0 · Estimate: 2 d · Owner: A · Provisional: no

## Goal
A test helper that builds a complete, byte-identical git repository from a declarative spec, so every
later scenario can assert exact SHAs and exact merge outcomes.

## Dependencies
T-0001. Architecture `11` §2. ADR-0007 (determinism envelope concepts, applied to fixtures).

**Reuse, do not re-invent.** The verified SP-1R3 environment is the reference the forge must reproduce: `env -i`, `LANG=C LC_ALL=C TZ=UTC`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_SYSTEM=/dev/null`, `core.hooksPath` empty, `core.attributesFile=/dev/null`. The identity and dates are not one rule, and the evidence fixes each: **fixture commits** (the forge's base and source commits) use `fixture <fixture@example.com>` and the single date `2020-01-01T00:00:00Z` for every commit, as the SP-1R3 `sp1_env` defaults do (`testdata/reference/lib.sh`); the oracle's base SHAs depend on this. **Integration merges** (the candidate built by `fixtures.Integrate`, as `testdata/reference/oracle.py` builds it) use `ilvuno <ilvuno@localhost>` as author and committer, with the base commit's committer time as both dates (`expected.json` metadata: `ilvuno <ilvuno@localhost> @<base commit time>`). Sources: `docs/experiments/scripts/README.md` and `docs/experiments/sp1-recommendation.md` (H-7).

## Allowed file scope
- `internal/testkit/forge/**`
- `internal/testkit/forge/testdata/` (spec files only)
- `Makefile` (add `forge-verify`)

**May not touch:** production packages; any write outside the module cache and `t.TempDir()`.

## Implementation outline
1. `Spec{Base, Files, Branches, Tags}` → build in `t.TempDir()`.
2. Force `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_SYSTEM=/dev/null`, `TZ=UTC`, fixed
   `GIT_AUTHOR_*`/`GIT_COMMITTER_*`, fixed dates per commit (deterministic sequence), `umask 022`.
3. Branch creation from a named base with per-file `Changes` (write/append/delete/rename).
4. Optional conflict construction helper: `ConflictingEdits(path, rangeA, rangeB)`.
5. `Spec.Build(t)` returns a handle: `Path`, `SHA(ref)`, `Run(git args…)`, `Snapshot()`.
6. Snapshot = refs→SHA map + tree SHA + index digest, for equality assertions.
7. Self-test: build the same spec twice, assert identical snapshots; build on two specs and assert
   they differ where expected.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | Two builds of one spec in the same process produce identical refs and tree SHAs |
| AC-2 | A build ignores the developer's global/system git config (test sets a hostile `~/.gitconfig`) |
| AC-3 | Commit dates are fixed and reproducible (assert exact `%ct` values) |
| AC-4 | Conflict helper produces a real conflict (assert `git merge` exit ≠ 0) |
| AC-5 | Forge self-tests run in < 2 s for 10 fixtures |
| AC-6 | No network access in any forge path (test with `GIT_ALLOW_PROTOCOL=none` + an unreachable remote) |
| AC-7 | For fixtures F1–F10, the forge-built base SHA equals the `base` recorded for the same fixture in `testdata/reference/oracle.json` (T-0005). Any source-SHA difference is documented with its cause |

## Test commands
```
go test ./internal/testkit/forge/... -count=1 -v
make forge-verify
```

## Evidence requirements
Self-test log, two snapshot dumps proving identity, hostile-config test output.

## Review checklist
- No dependency on the real clock or `$HOME`.
- Snapshot includes refs, tree, index — not just HEAD.
- Errors from git are surfaced with argv + stderr (not swallowed).
- Forge cannot accidentally write outside `t.TempDir()` (path prefix assertion).

## Implementation notes (2026-11-20)

> **Historical implementation report (2026-11-20).** Everything below reports tests and implementation
> observed in the **uncommitted M0 working tree**. None of it is reproducible from the committed
> governance HEAD (`docs/commit-rules`); the code and its harness land with PR-2. The task requirements,
> acceptance criteria and the D-19 scope amendment above are unaffected.

- **Deviation from the outline:** steps 1–5 proposed a declarative `Spec`. The forge exposes an imperative `Repo` API (`WriteFile`, `Commit`, `Branch`, `Checkout`, `SetLine`, `Chmod`, `AddWorktree`, `RemoveWorktree`, `Snapshot`). The F5, F6 and F7 fixtures need steps (merge into main, orphan branch, base commit on top of a base commit) that a flat spec expresses poorly.
- **Environment:** the SP-1R3 identity and dates, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_ALLOW_PROTOCOL=none`, empty `core.hooksPath`, `core.attributesFile=/dev/null`. The environment is built from scratch, not inherited.
- **AC-7** is implemented by the fixture tests (`internal/testkit/fixtures`), which compare forge base and source SHAs with `testdata/reference/oracle.json`. All ten SP-1R3 fixtures match on base and source SHAs. Candidate SHAs are compared for the nine ported fixtures (F1–F8, F10); F9 is a fault-injection case. *(These results were observed on the uncommitted M0 working tree; the task's requirements are unchanged.)*
- **Evidence (2026-11-20, uncommitted working tree):** `make forge-verify` (68 PASS, 0 FAIL), and the race detector on all packages. The runs used the M0 working tree; no M0 code is committed at the governance HEAD, so the result is not reproducible from `docs/commit-rules` until PR-2 lands. Requirements are unchanged; gate status is in `docs/readiness/06` §4.
