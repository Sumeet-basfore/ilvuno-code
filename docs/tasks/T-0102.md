# T-0102 — Repo discovery and refusals

Milestone: M1 · Estimate: 1 d · Owner: B · Provisional: no

## Goal
Decide, before anything else happens, whether this repository is in a state Ilvuno can reason about —
and refuse with a specific reason and a fix command when it is not.

## Dependencies
T-0101.

## Allowed file scope
- `internal/repo/**`
- `internal/model/` (only the `RepoCondition` enum; coordinate with T-0301)

**May not touch:** `internal/engine`, `internal/journal`.

## Implementation outline
1. `Discover(ctx, path) (Repo, error)` resolving: toplevel, git-common-dir, is-shallow, is-bare,
   `.git` file vs dir (submodule), `core.worktree`, sparse-checkout, LFS presence when LFS files are
   tracked, nested-candidate detection.
2. Each refusal is a typed error with code (`repo_bare`, `repo_shallow`, `repo_submodule`,
   `repo_sparse`, `repo_lfs_missing`, `repo_unusual_layout`, `repo_nested_candidate`) and a `next`
   command.
3. Lazy probes: never run a probe whose result is unused (keep `integrate` fast).
4. Nested detection: true when the repo root path is inside a directory that contains a journal
   referencing `refs/ilvuno/candidates/*`.
5. Table test per condition, using fixtures from T-0003 and forge variants.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | All seven conditions produce their exact code (table test, one row per code) |
| AC-2 | Each error message contains a runnable fix (e.g. `git sparse-checkout disable`) |
| AC-3 | A normal repo produces zero warnings and discovers in ≤ 20 ms |
| AC-4 | Shallow is refused only when merge-base is needed (a `show`-only path may still work) |
| AC-5 | Discovery never writes (fingerprint unchanged) |
| AC-6 | No absolute path appears in any error (only repo-relative) |

## Test commands
```
go test ./internal/repo/... -count=1 -v
```

## Evidence requirements
Table: condition → code → message → fix. Timing for the normal case.

## Review checklist
- Are refusals *refusals* (exit 2) rather than warnings that let a wrong merge proceed?
- Is "shallow" scoped correctly (don't break commands that do not need history)?
- Does the nested-candidate check avoid a false positive when `.ilvuno/` is absent?
