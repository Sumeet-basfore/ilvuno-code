# T-0603 — Repair loop (external command)

Milestone: M6 · Estimate: 1.5 d · Owner: A · Provisional: no

## Goal
A bounded, recorded repair attempt that uses whatever tool the developer already has, without Ilvuno
embedding an agent or touching a source branch.

## Dependencies
T-0402, T-0403, T-0304. ADR-0011, `INT-501`..`INT-506`.

## Allowed file scope
- `internal/repair/**`
- `internal/cli/repair.go`
- `docs/repair.md`

**May not touch:** `internal/agent` (does not exist in MVP), source refs.

## Implementation outline
1. Brief builder (deterministic): failing command, exit, redacted output tail (≤4 KiB), per-source
   "alone" results, sources with SHAs, the "do not modify sources" constraint, deliverable statement.
2. Write the brief to `<repair-worktree>/.ilvuno-brief.md` and on stdin.
3. Per attempt: new branch `refs/ilvuno/repair/<run_id>-<n>`, new worktree off the candidate, spawn the
   configured command, capture exit + produced refs (via git observation only).
4. Re-verify the new HEAD (T-0404); on pass, return repaired; on fail, record attempt and loop.
5. Budget: default 2, max 5; each attempt's diff archived under the run dir; exhaustion → escalation
   block with a diagnosis (interface mismatch vs flake) from deterministic evidence.
6. Refuse: missing command config, candidate not failed, budget already exhausted, or a source ref
   changed since the candidate was built.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | Brief is deterministic (same evidence → byte-identical brief) |
| AC-2 | Sources are byte-identical before/after any repair (`INT-505`) |
| AC-3 | Attempts are independent branches; every diff is archived, including failures |
| AC-4 | A no-op repair (exit 0, no commit) counts as a failed attempt |
| AC-5 | Budget exhaustion yields `budget_exhausted` + escalation block, exit 1 |
| AC-6 | A successful repair re-verifies and reports the new candidate SHA + attempt count |
| AC-7 | The configured command receives the brief on stdin and in the worktree, and nothing else |

## Test commands
```
go test ./internal/repair/... -count=1 -v
make bench SCENARIO=B-13
```

## Evidence requirements
A 2-attempt failure transcript, a success transcript, archived diffs, source-SHA equality proof.

## Review checklist
- Could a repair attempt modify a source branch indirectly (e.g. `git checkout -B`)? (must be prevented
  by cwd + ref checks, and asserted)
- Is the brief free of model-generated text?
- Does the loop ever exceed the budget (off-by-one)?
- Is every failed attempt visible in the report rather than summarised away?
