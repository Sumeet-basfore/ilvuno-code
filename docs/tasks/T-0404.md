# T-0404 — `verify` command, tree integrity, `--runs`

Milestone: M4 · Estimate: 1 d · Owner: B · Provisional: no

## Goal
Make verification reachable for an existing candidate or branch head, and make it impossible to
silently verify a moving target.

## Dependencies
T-0401..T-0403, T-0205. `INT-307`/`INT-308`, `VER-104`, architecture `07` §6.

## Allowed file scope
- `internal/cli/verify.go`
- `internal/verify/integrity.go`
- `internal/engine/verify_candidate.go`

**May not touch:** report templates beyond an additive warning.

## Implementation outline
1. `ilvuno verify --candidate <sha|run>` or `--ref <ref>` (pinned first, then verified as a SHA).
2. Integrity bracket: `tree_before`, `HEAD_before`, then after: `HEAD_after`, `tree_after`,
   `status --porcelain` (tracked). Rules: HEAD change → `candidate_mutated` failure; tracked changes →
   warning + file list; untracked → `outputs[]`.
3. `--runs N` (1..3): re-run the pipeline on the same SHA; mixed results → `failed` + `flaky_check`
   naming the command. Never converts a failure into a pass.
4. `--json` output for the verification result; exit codes from T-0402.
5. SIGINT handling: terminate group, journal `interrupted`, exit 130 (state machine in T-0501).
6. Guard: verifying a ref whose SHA differs from the run's candidate is refused unless `--allow-mismatch`
   (which records the mismatch in the report).

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | A command that commits yields `candidate_mutated`, exit 1, result not attributable |
| AC-2 | A command that modifies tracked files yields a warning + file list, result still bound to the SHA |
| AC-3 | `--runs 2` with mixed results yields `failed` + `flaky_check` |
| AC-4 | SIGINT mid-run exits 130 and leaves a resumable journal |
| AC-5 | Verifying a mismatched SHA is refused without `--allow-mismatch` |
| AC-6 | `--json` validates against the report schema |
| AC-7 | `verify` on an unchanged candidate reuses the cached result (with `--cached`, default on) |

## Test commands

## Evidence requirements
Integrity transcripts (commit case, modified case), flaky-run output, exit-code matrix row.

## Review checklist
- Can a result be attributed to a SHA it was not run on? (must be impossible)
- Does `--runs` ever turn mixed into passed?
- Is the warning list capped and repo-relative?
