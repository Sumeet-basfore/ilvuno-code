# T-0601 — Passport v1

Milestone: M6 · Estimate: 1.5 d · Owner: A · Provisional: no

## Goal
A durable, human-readable task record that survives machines and weeks, with derived state and an
integrity chain that makes hand- and agent-edits visible.

## Dependencies
T-0301 (model), T-0304 (evidence refs), T-0501 (state names). `TSK-101`..`TSK-112`, ADR-0014.

## Allowed file scope
- `internal/passport/**`
- `schemas/passport.schema.json`
- `internal/cli/task.go`
- `docs/passport.md`, `docs/ilvuno/passport.example.yaml`

**May not touch:** evidence store internals (refs only), approval records (T-0602).

## Implementation outline
1. Schema `ilvuno.dev/passport/v1` per architecture `02` §3.14; strict decode; unknown keys rejected
   (forward-compat handled by `x-` prefixed extensions only).
2. Read: validate → recompute `digest_chain` over the semantic body → if mismatch, render `tampered`
   and mark approvals `unverifiable`; never auto-repair.
3. Write protocol: temp file in the same dir → fsync → validate → rename → fsync(dir); refuse if the
   on-disk digest differs from the last read (`passport_conflict` + diff).
4. Derived `state` and `next_actions` functions (pure, deterministic, permutation-stable).
5. `task new|show|list`; `show` renders: objective, criteria with verification status, decisions,
   streams with SHAs, verification refs (resolving bundles), pending approvals, next actions,
   `not_included`.
6. Dangling SHA / missing bundle handling: render `evidence_missing` / `dangling_ref` with a fetch
   hint; never silently drop.
7. Portability lint: no absolute paths, no hostnames, no timestamps outside `at` fields.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | A hand-edited approval or state field breaks the chain → `tampered`, gate closed |
| AC-2 | `state` and `next_actions` are derived; hand-set values are ignored and reported |
| AC-3 | A passport renders identically from a clean clone on a second machine |
| AC-4 | Concurrent edit is refused with a diff, not merged |
| AC-5 | Missing bundle renders `evidence_missing`, and status never shows `passed` |
| AC-6 | A decision change requires a new record with `supersedes`, not an edit |
| AC-7 | No absolute path or host identifier appears in any passport fixture |

## Test commands

## Evidence requirements
Two-machine render transcripts, tamper test output, conflict-diff sample.

## Review checklist
- Is the chain over the semantic body only (so derived recomputation does not break it)?
- Does any code path "fix" a tampered passport?
- Is `not_included` always present?
- Does `show` work with the tool's own evidence directory deleted?
