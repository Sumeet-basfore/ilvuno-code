# T-0303 — Dependency and interface analysis

Milestone: M3 · Estimate: 1.5 d · Owner: B · Provisional: no

## Goal
Catch the two failure classes that git cannot see: two streams pinning different versions of the same
dependency, and one stream changing an exported symbol another stream calls.

## Dependencies
T-0301, T-0302 (file lists). `INT-203`, `INT-204`.

## Allowed file scope
- `internal/analyze/deps.go`, `internal/analyze/interface.go`
- `internal/analyze/parsers/` (one file per manifest kind)
- `internal/analyze/testdata/manifests/`

**May not touch:** `internal/verify`.

## Implementation outline
1. Parser registry: `package.json` (deps/devDeps/peerDeps), `pnpm-lock.yaml` (churn detection only),
   `go.mod`, `Cargo.toml`. Unknown manifest → `manifest_unparsed` info (never guessed).
2. Per source: collect declarations `{name, constraint, kind}` from changed manifests.
3. `dependency_disagreement`: same name, different constraint across ≥2 sources → finding with both
   SHAs and constraints; blocking per config (`on_dependency_conflict ∈ {block, warn}`).
4. `lockfile_churn`: lockfile changed with no declaration change → info.
5. Interface pass (requires `analysis.index_command`): run the command in each source's worktree,
   parse a documented line format (`symbol<TAB>file<TAB>line`), diff symbol sets, then correlate with
   other sources' changed files. Finding: `interface_symbol_touched`, warning.
6. If no index command: emit `interface_analysis_skipped` info so `not_verified` is honest.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | `B-09` yields one `dependency_disagreement` with both constraints and SHAs |
| AC-2 | With `on_dependency_conflict = warn`, `B-09` is non-blocking but still present |
| AC-3 | `B-10` yields `lockfile_churn` info only |
| AC-4 | An unknown manifest yields `manifest_unparsed` and no constraint claims |
| AC-5 | `B-08` with an index command yields `interface_symbol_touched` naming the symbol |
| AC-6 | Without an index command, `interface_analysis_skipped` appears in `not_verified` |
| AC-7 | No parser executes project code (parsers read files only) |

## Test commands
```
go test ./internal/analyze/ -run 'TestDeps|TestInterface' -count=1 -v
make bench SCENARIO=B-09; make bench SCENARIO=B-10
```

## Evidence requirements
Findings JSON for B-08/B-09/B-10; parser table (manifest → parsed fields); skipped-analysis output.

## Review checklist
- Does a parser ever *infer* a version from a lockfile only? (no — declarations only)
- Is the index command run in the candidate or in per-source worktrees? (per-source, and cleanly)
- Can a malicious index command write outside its worktree? (documented: it runs as the user)
- Is the "skipped" state visible rather than silently absent?
