`internal/lint/importrule`), the dependency rules from `architecture/01` §3 enforced by a test, and

## Implementation outline
1. `go mod init github.com/Sumeet-basfore/ilvuno-code` (D-17); pin the Go toolchain version in
   `go.mod`; no third-party deps.
2. `cmd/ilvuno`: `--version` prints `ilvuno dev` and exits 0; `--help` lists planned commands as
   "not implemented in this build" (honest, not fake).
3. No package stubs. `cmd/ilvuno` imports nothing from `internal/`.
4. `internal/lint/importrule`: a test-only analyzer asserting the dependency matrix.
5. `Makefile` targets: `build`, `test`, `lint`, `docs-check`, `bench`, `gate`.
   - `test`: `go test ./...`
   - `lint`: `gofmt -l` over tracked Go files (fail on any output) + `go vet ./...` +
     `go test ./internal/lint/importrule/...` so the dependency rule is enforced by `make lint`.
   - **Approved M0 lint scope (D-16, 2026-11-20):** `gofmt`, `go vet` and the in-repository
     import-rule test. **No `staticcheck` and no `golangci-lint` in M0.** `staticcheck` remains the
     target bar and is deferred until separately approved as a tool dependency; AGENTS §4.1 records
     the M0 exception. This task installs no lint tool and adds no dependency.
   - `bench` and `gate` print "not implemented" and exit 2 until their tasks land
     (`docs/readiness/06` §3.1). `forge-verify` is added by T-0002.
   - `reference-matrix` and `reference-tests` are added by T-0005, not here.
6. CI: T-0001 **creates** `.github/workflows/ci.yml` with a matrix (ubuntu-latest, macos-latest) ×
   (`build`, `test`, `lint`); `GIT_CONFIG_GLOBAL=/dev/null`; `git --version` printed; fail below Git
   2.38.1 (D-05). CI scope approved 2026-11-20 (S-4); the workflow file is reviewed before merge
   (AGENTS §10.2).
   - **CI ownership:** T-0001 owns the workflow and contains **no reference-harness job**. T-0005
     subsequently adds the reference-matrix, reference-tests, and failing-Git jobs to this workflow
     (its own allowed scope and review). The macOS reference run required before G0 is a T-0005
     acceptance criterion, not a T-0001 one.
7. License and community files; `.gitignore` includes `.ilvuno/`, `ilvuno` binary, coverage files.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | Linux: `CGO_ENABLED=0 make build`; `ldd ./ilvuno` reports "not a dynamic executable" (or only `libc`/`ld-linux`); no non-system libraries |
| AC-1b | macOS: `CGO_ENABLED=0 make build`; `otool -L ./ilvuno` lists only `/usr/lib/*` and `/System/*` paths |
| AC-2 | `make test` passes on a clean clone with `GIT_CONFIG_GLOBAL=/dev/null` and no network |
| AC-3 | `make lint` fails when a fixture under `internal/lint/importrule/testdata/` imports a package forbidden by the matrix (proves the analyzer is wired into `lint`) |
| AC-4 | CI is green on both OSes for `build`, `test`, `lint`, and prints the Git version; the workflow contains no reference-harness job (T-0005 adds those) |
| AC-5 | `ilvuno --version` exits 0 in ≤ 30 ms |
| AC-6 | README states the product in one paragraph, the non-goals, and a "not usable yet" banner |
| AC-7 | `go.mod`'s module directive is exactly `github.com/Sumeet-basfore/ilvuno-code`; it matches every internal import path and the repository URL recorded in D-17 |
