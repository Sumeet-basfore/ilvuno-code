# T-0301 — Model + findings schema

Milestone: M3 · Estimate: 1.5 d · Owner: B · Provisional: no

## Goal
A typed domain layer whose constructors make the load-bearing invariants unrepresentable to violate,
plus the finding schema that separates deterministic facts from interpretations.

## Dependencies
T-0205 (candidate exists). Architecture `02` §3–§8, ADR-0014.

## Allowed file scope
- `internal/model/**`
- `schemas/{report,findings}.schema.json`
- `docs/schemas.md`

**May not touch:** `internal/analyze`, `internal/evidence` (consume the model).

## Implementation outline
1. Entities (subset for M3): `Project`, `IntegrationRun`, `PinnedSource`, `MergeStep`,
   `IntegrationCandidate`, `Finding`, `EvidenceRef`. IDs per `02` §2 with a single generator.
2. Constructors (`NewFinding`, `NewCandidate`, …) validate: non-empty IDs, SHA format, `classification`
   ∈ {deterministic, interpretation}, `severity: blocking ⇒ deterministic`, evidence refs present for
   `deterministic`.
3. `Finding.Validate()` returns typed errors; a `blocking` + `interpretation` combination is
   impossible to construct through the public API (no exported fields on `Finding`).
4. JSON schema `ilvuno.dev/findings/v1` mirrors the Go types; a contract test round-trips
   model → JSON → schema validation → model.
5. State-transition functions for `IntegrationRun` (the M3 subset: planned→…→verified) with illegal
   transitions returning typed errors.
6. No method that maps `AgentRun` (even a stub) to an approval or a passed verification (`INV-7`
   absence test, `T-COMP-4`).

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | Constructing a `blocking` interpretation fails at construction time (not at render) |
| AC-2 | A `passed` evidence ref without a commit SHA fails validation (`C-7`) |
| AC-3 | Round-trip model → JSON → schema → model is lossless for all fixtures |
| AC-4 | An illegal state transition returns a typed error naming both states |
| AC-5 | The absence test `T-COMP-4` finds no mapping from agent completion to a verdict |
| AC-6 | Identifiers are stable across a serialization round-trip and contain no path/time-derived data (except `irn_`/`run_` timestamps, documented) |

## Test commands
```
go test ./internal/model/... -count=1 -v
go test ./internal/model/ -run TestAbsence -count=1 -v
```

## Evidence requirements
Constructor-failure table, schema round-trip log, the absence-test source and result.

## Review checklist
- Are entity fields exported (allowing bypass of constructors)? (they must not be)
- Does the schema permit anything the model forbids, or vice versa?
- Is `classification` defaulted anywhere? (must be explicit)
