# T-0202 — Policy gate + worktree lifecycle

Milestone: M2 · Estimate: 2 d · Owner: A · Provisional: no

## Goal
The only place the product is allowed to mutate a repository: a single write-scope gate, and a
worktree lifecycle that creates, rolls back, and removes disposable worktrees without ever touching
user state.

## Dependencies
T-0101, T-0105, T-0201. ADR-0006, `INV-1`/`INV-11`, architecture `05` §4, §7.

## Allowed file scope
- `internal/policy/**`
- `internal/gitx/worktree_add.go`, `worktree_remove.go`
- `internal/engine/worktree.go`

**May not touch:** `internal/cli` (commands arrive in T-0205), `internal/verify`.

## Implementation outline
1. `policy.AllowWrite(path)` / `AllowRef(ref)`: resolve symlinks + `..`, assert the result is under
   `.ilvuno/` or `docs/ilvuno/tasks/`; refs must be exactly `refs/ilvuno/<kind>/<id>` (prefix on the
   qualified name).
2. `WorktreeAdd(runID, kind, baseSHA)`: `worktree add --no-checkout -B <ref> <path> <sha>` then
   `reset --hard`; on failure run rollback and return the error with the attempted argv.
3. `WorktreeRemove`: archive `candidate.patch` when dirty (digest recorded), `remove --force` (only for
   our refs), `update-ref -d` (fully qualified), `worktree prune`; on failure mark `orphaned` in the
   journal rather than throwing.
4. Every call is preceded by a journal `*.intent` record and followed by `*.result` (T-0201 API).
5. Concurrency guard: refuse a 5th concurrent worktree for the project (limit 4).
6. Tests: fault injection at each of 5 stages; safety fingerprint before/after; user-worktree removal
   attempt is refused.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | Any path outside the two roots is refused (`write_outside_scope`, exit 2) |
| AC-2 | Any ref not matching `refs/ilvuno/<kind>/<id>` is refused |
| AC-3 | After a forced failure at each stage, no orphan worktree or ref remains (or it is `orphaned` and reported) |
| AC-4 | A dirty candidate is patched before removal; the patch digest is in the journal |
| AC-5 | A crafted journal targeting a user worktree cannot cause its removal (`T-SEC-4`) |
| AC-6 | Candidate commits never run repo hooks and are never signed (`gitenv` metadata asserted) |
| AC-7 | Safety fingerprint unchanged in all success and failure cases |

## Test commands
```
go test ./internal/policy/... ./internal/engine/ -run 'TestWorktree|TestPolicy|TestSafety' -count=1 -v
```

## Evidence requirements
Fault-injection table (stage → resulting state → orphan count), fingerprint diffs, patch artefact.

## Review checklist
- Is the gate bypassable by any caller (does anything call `os.RemoveAll` directly)?
- Does `--force` ever apply to a non-`refs/ilvuno/` worktree?
- Is `update-ref -d` given the fully qualified ref, never a bare name?
- Does rollback itself journal, so a rollback failure is visible?
