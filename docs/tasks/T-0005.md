## Status of the original task
Withdrawn, and not answered. The original question was whether `git merge-tree --write-tree` detects a
conflict that exists only for the full tuple of three branches. The question no longer decides anything:

- `merge-tree --write-tree` accepts exactly two commits (X-02, `docs/readiness/02` §2; three commits exit 129).
- The candidate is built by sequential two-way merges. The SP-1R3 harness is the reference for that behaviour
  (`docs/experiments/`), and `docs/experiments/sp1-recommendation.md` §6 treats the E-1′ question as answered.

## Goal
After this task, a reproducible reference oracle sits in the repository's test infrastructure. Its conformance
on each supported Git version is recorded, and it runs under the SP-1R3 **operational conditions R3-1…R3-4**
below. The older `C-1…C-9` identifiers are retained only as historical remediation labels in
`docs/reviews/sp1r3-closure-evidence.md`; they are not verdict conditions and must not be cited as such.

### SP-1R3 operational conditions (derived from the verdict; not owner decisions)

| ID | Condition |
|---|---|
| **R3-1** | Each run uses a fresh canonical private scratch root: absolute, mode 700, not a symlink, outside the work tree. Never reuse a failed or interrupted root. |
| **R3-2** | Every command's exit status is checked; the runner stops at the first nonzero. No output from a failed step may be consumed. |
| **R3-3** | `oracle.json` is generated into a fresh temporary copy. A failed oracle invocation invalidates its output; the runner must not read a pre-existing oracle file after a failure. |
| **R3-4** | The ownership marker, fixture registry and `run-env.json` are editable consistency guards, not attestations. The harness trusts its own process; no same-UID adversary is in scope. |

## Implementation outline
1. Copy the SP-1R3 files into `testdata/reference/`. Do not edit `docs/experiments/`.
2. C-5 (approved): replace the three literal `/tmp/r3-cl` references (lines 398, 399 and 401) with `$T/r3-cl`, where `T=$SP1_SCRATCH/tests` is already defined. Show the
   diff in the note. Change no assertion.
3. Path preflight, oracle freshness and failure handling (R3-1…R3-3). `check-reference.sh` implements this contract;
   the sketch below is a specification, not committed code.

   - **Path preflight, before every repository-writing Git operation in every mode.** The preflight
     applies to all wrapper modes (`oracle`, `matrix`, `tests`), not only oracle generation. Every
     supplied or derived root must be absolute and canonical (no `.`, `..`, duplicate separators, or symlink
     component at or below the supplied root; the platform temporary base is canonicalised first),
     an existing directory, owned by the invoking uid, mode 700 (no group or other permission bits),
     and outside the worktree (canonical comparison against the read-only
     `git rev-parse --show-toplevel`). A path that resolves through a symlink, aliases another
     location, or fails any check is rejected nonzero before the oracle, comparison, or the first
     command that could write a worktree, merge, ref, index or object. The worktree comparison itself
     uses only read-only Git commands.
   - **Fresh private copy (R3-1).** Create a private temporary root with `mktemp -d`, `chmod 700`,
     copy `testdata/reference` into it with `cp -a`, then create a separate private scratch parent
     with `mktemp -d` and `chmod 700`. Record each root this invocation creates; cleanup deletes only
     those recorded roots and never a path supplied by the caller. The oracle never runs in the
     tracked reference directory.
   - **Setup gate.** Delete the copied `oracle.json` before invoking the oracle. The oracle is
     invoked only if every setup command (`mktemp`, `chmod`, `cp`, `rm`) exited 0; any setup failure
     aborts nonzero without running the oracle and without reading or comparing any oracle output.
   - **Checked operations.** The exit status of every setup, oracle, comparison and cleanup command
     is checked. A nonzero oracle status aborts before any comparison. A failed `cmp` runs `diff -u`
     and exits nonzero. No command's output is consumed after that command fails.
   - **Cleanup handler.** Install an `EXIT` trap before creating the first temporary directory. The
     handler captures the original status, removes both temporary roots, and exits with that original
     status. If cleanup fails and the original status was 0, the handler exits nonzero; if the run had
     already failed, the original nonzero status is preserved and the cleanup failure is reported on
     stderr. The handler must not mask a failure and must not run twice.
   - **No stale reads.** The tracked `oracle.json` is never overwritten, and the comparison is
     reachable only through the success path above. Comparing after a failed setup or oracle command
     does not satisfy R3-3.

   Pseudocode shape (not committed code). Every mode begins with the same `validate_root` call;
   `matrix` and `tests` run it before their first repository-writing Git command, and `oracle` runs it
   before generation. The sequence below is oracle mode; the other modes reuse the preflight and the
   cleanup handler, and skip only the oracle/cmp steps.

   ```
   validate_root "$SP1_SCRATCH" || exit 1   # read-only checks; may call git rev-parse
   tmp= parent=
   cleanup() {
     rc=$?
     trap - EXIT
     for d in "$tmp" "$parent"; do
       [ -n "$d" ] || continue
       rm -rf "$d" || { echo "cleanup failed: $d" >&2; [ "$rc" -ne 0 ] || rc=1; }
     done
     exit "$rc"
   }
   trap cleanup EXIT
   tmp=$(mktemp -d) || exit 1; chmod 700 "$tmp" || exit 1
   cp -a testdata/reference "$tmp/ref" || exit 1
   parent=$(mktemp -d) || exit 1; chmod 700 "$parent" || exit 1
   rm -f "$tmp/ref/oracle.json" || exit 1
   SP1_SCRATCH="$parent" SP1_GIT_BIN="$(command -v git)" "$tmp/ref/sp1.sh" oracle || exit 1
   cmp "$tmp/ref/oracle.json" testdata/reference/oracle.json || { diff -u testdata/reference/oracle.json "$tmp/ref/oracle.json"; exit 1; }
   # matrix/tests: the same `validate_root "$SP1_SCRATCH" || exit 1` runs before
   # "$SP1_REF/sp1.sh" <mode> or tests.sh, so the first Git write happens only after validation.
   ```
   The committed `oracle.json` is never overwritten and never read after a failed setup or oracle
   command. `check-reference.sh` must fail loudly if any setup, oracle, comparison or cleanup step
   fails, and must not print passing evidence after any failure.
4. `make reference-matrix` runs `check-reference.sh matrix`: path preflight before the runner's first
   repository-writing Git command (no worktree, merge, ref or object write on an invalid root), a fresh
   mode-700 parent (R3-1), `set -euo pipefail`, fail on any nonzero command (R3-2), and fail when
   `run-env.json` does not report exactly `2.55.0` or `2.38.1`. The `tests` mode runs the same
   preflight before its first Git write. `make reference-tests` runs the wrapper's negative tests (AC-9…AC-13) and
   then `tests.sh`.
5. Run the matrix and `tests.sh` on Git **2.55.0** (host) and Git **2.38.1** only. For 2.38.1 use
   `ilvuno-git238r:rebuild-2026-11-20`, image ID
   `sha256:1044b988f91593334ab23b73b7b8ecbb308e49eda57c81ed86851677ef6fe859`
   (`docs/research/09-git-floor.md` §0). Record the image ID, the Git version printed inside the
   container, the Python 3 version, and each `run-env.json`. `2.55.x` is not a supported label.
6. Update `docs/research/09-git-floor.md` with the T-0005 run. The X-09 note was written on 2026-11-20 as E-10 evidence, and its gaps are listed in §4.
