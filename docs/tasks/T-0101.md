# T-0101 — gitx exec wrapper + version probe

Milestone: M1 · Estimate: 1.5 d · Owner: A · Provisional: no

## Goal
One package that invokes `git` correctly and identically every time: explicit argv, forced config,
stable locale, documented-output parsing, typed errors, and a probed capability set. No other package
may call `git` directly.

## Dependencies
T-0001. ADR-0004 (subprocess only), ADR-0005 (no ref re-resolution).

## Allowed file scope
- `internal/gitx/**`
- `internal/policy/**` (read-only use; the write gate lands in T-0202)

**May not touch:** `internal/engine`, `internal/verify`, `internal/analyze`.

## Implementation outline
1. `Runner` interface: `Run(ctx, args...) (stdout, stderr, exit) ` with a fixed base argv:
   `git -c gc.auto=0 -c core.quotepath=false -c core.hooksPath= -c commit.gpgsign=false
   -c merge.conflictStyle=merge --no-pager -C <dir>` plus `LC_ALL=C`.
2. Argv is a slice, never a shell string. A test asserts no call path concatenates a string.
3. `Output` helpers for documented formats only: `RevParse`, `ForEachRef`, `LsTree(-z)`,
   `MergeTree`, `StatusPorcelainV2`, `RevListCount`, `CatFileExists`, `WorktreeList`.
4. Typed errors: `ErrNotARepo`, `ErrGitMissing`, `ErrGitTooOld`, `ErrGitLocked`, `ErrObjectMissing`,
   each with a stable code and a `Next` action.
5. `Probe()`: version, `merge-tree --write-tree` support, worktree support, `--porcelain=v2`
   support; returns a `Capabilities` struct recorded in every run.
6. Retry on `.git/index.lock` contention: ≤ 3 attempts over ~2 s, then `ErrGitLocked`.
7. Redaction-safe error surface: stderr is captured but truncated to 4 KiB and passed through the
   redactor before being attached to an error.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | No package outside `gitx` executes `git` (import-rule test + grep assertion) |
| AC-2 | `Probe()` reports version and `merge_tree` support accurately on 2.38 and latest |
| AC-3 | `MergeTree` parses only `--write-tree` output; a human-output format is never parsed |
| AC-4 | A locked index yields `ErrGitLocked` after bounded retries with a clear `Next` |
| AC-5 | All errors carry `code`, `class`, `message`, `next` and no absolute path |
| AC-6 | `-z` parsing survives filenames with spaces, newlines, and non-ASCII |

## Test commands
```
go test ./internal/gitx/... -count=1 -v
go test ./internal/lint/importrule/... -count=1
```

## Evidence requirements
Capability probe output on both CI OSes; a table of parse cases with weird filenames.

## Review checklist
- Is any git output parsed that is documented as human-facing? (reject)
- Are forced `-c` flags exactly the ADR-0004 list, no extras that could change user semantics?
- Does the retry ever run a *mutating* command twice? (must not)
- Is stderr redacted before it can reach a log or an error message?
