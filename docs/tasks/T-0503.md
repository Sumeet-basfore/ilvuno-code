# T-0503 — Crash harness and signal matrix

Milestone: M5 · Estimate: 2 d · Owner: A · Provisional: no

## Goal
Prove interruption behaviour mechanically: die at every stage, every signal, and assert the invariants
every time.

## Dependencies
T-0501, T-0205, T-0404. Architecture `11` §7.

## Allowed file scope
- `internal/testhooks/**` (`//go:build testhooks`)
- `internal/testkit/crash/**`
- `.github/workflows/crash.yml`
- `docs/crash-matrix.md` (generated table committed)

**May not touch:** production code paths except the single `testhooks.DieAfter(stage)` call site,
which must be a no-op without the build tag (asserted by a test).

## Implementation outline
1. `testhooks.DieAfter(stage)` reading `ILVUNO_TEST_DIE_AFTER`, implemented as `os.Exit(137)` at the
   named boundary; compiled only with the tag.
2. Stage list (12): fetch, pin, preflight, worktree_add, merge_begin, merge_end, verify_start,
   verify_command, verify_end, seal_begin, seal_end, cleanup.
3. Matrix runner: for each stage × {SIGKILL (via hook), SIGTERM, SIGINT} run a scenario, then assert:
   journal parses; state ∈ {interrupted, settled}; no orphan worktree/ref/process; fingerprint equal
   (except `.ilvuno/`); `resume` either completes or refuses with a typed reason.
4. Timeout per case (30 s) so a hang is a failure, not a stuck CI.
5. Emit `crash-matrix.md` (stage × signal → state → resume outcome) and fail if any cell is
   undefined.
6. CI job: PRs touching `engine`/`journal`/`verify`, nightly otherwise.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | 36 cells (12 stages × 3 signals) all produce a defined outcome |
| AC-2 | Zero orphans across the matrix (worktrees, refs, child processes) |
| AC-3 | `resume` succeeds or refuses with a typed reason in every cell |
| AC-4 | Safety fingerprint unchanged in every cell (except `.ilvuno/`) |
| AC-5 | Without the build tag, `testhooks` is a no-op (asserted by a production build test) |
| AC-6 | The matrix runs in ≤ 12 minutes on CI (documented if parallelised) |
| AC-7 | The generated table is committed and `make docs-check` fails if it drifts |

## Test commands
```
go test -tags testhooks ./internal/testkit/crash/... -count=1 -v
make crash-matrix
```

## Evidence requirements
The committed matrix table, CI run link, orphan scan output for the worst case.

## Review checklist
- Does the hook ever run in a normal build?
- Is SIGTERM distinct from SIGKILL (graceful path vs hard path)?
- Are the assertions the same for every cell (no per-cell weakening)?
