# T-7002 — Claude adapter *(provisional)*

Milestone: M7 · **Provisional — not approved.** Estimate: 4 d · Owner: A

## Goal
Dispatch Claude Code through a documented surface, using the user's own binary and login, without
Ilvuno ever handling a credential.

## Dependencies
T-7001. ADR-0010, `AUTH-1..4`, `architecture/03` §2–§6.

## Allowed file scope
- `internal/agent/claude/**`
- `internal/testkit/conformance/claude/`
- `docs/adapters/claude.md`

**May not touch:** core packages; provider binaries are never bundled.

## Outline (sketch)
1. Prefer the Agent SDK (`query()` with `pathToClaudeCodeExecutable`) or stream-JSON CLI; choose by
   probe, record which surface was used.
2. Session: create/resume by provider session id; capability `ResumeAfterRestart` probed, never assumed.
3. Permissions: map to provider modes; **never auto-approve**; surface `permission.request` events.
4. Cancellation: interrupt → 2 s wait → SIGTERM group → SIGKILL group; record the rung.
5. Env: allowlist + scrub ambient provider vars we did not create.
6. Refusals: auth required, unsupported env (CI without login), protocol mismatch.
7. Conformance fixtures recorded once, replayed in CI (no live calls).

## Acceptance criteria (provisional)
- A missing/expired login yields `provider_auth_required`, not a retry loop.
- Cancellation kills the process group; no orphan survives.
- Unsupported environment is refused with a clear action.
- No credential is read, stored, or logged (asserted by a struct audit + env dump test).
- Provider version drift fails a conformance test, not a user's run.

## Test commands
```
go test ./internal/agent/claude/... -count=1
go test ./internal/testkit/conformance/claude/... -count=1
```

## Evidence requirements
Conformance replay log, cancellation transcript, env-dump test output.

## Review checklist
- Does the adapter ever prompt for or store a token?
- Is `StructuredEvents` true (otherwise dispatch must be refused)?
- Are provider-specific capabilities preserved rather than flattened away?
