# T-0203 — Determinism envelope

Milestone: M2 · Estimate: 1 d · Owner: B · Provisional: no

## Goal
Make commits produced by Ilvuno reproducible: same inputs, same SHA, regardless of when or where the
run happens (within a documented version band).

## Dependencies
T-0202. ADR-0007. Blocks T-0205 (candidate construction).

## Allowed file scope
- `internal/gitx/commit_env.go`
- `internal/engine/envelope.go`
- `docs/determinism.md`

**May not touch:** commit creation call sites (T-0205 wires them).

## Implementation outline
1. `Envelope(baseSHA)` → env map: fixed name/email `ilvuno`, fixed dates derived from the base commit
   time truncated to seconds, `TZ=UTC`.
2. Apply only to git invocations that create commits; never to user-facing commands.
3. Commit message builder: `ilvuno: integrate <sha[:12]> (step i/n)` — content-derived only. Version
   goes to `refs/ilvuno/meta/<run_id>` and the report.
4. `meta` ref content: `{ilvuno_version, git_version, os, arch, created_at}` (not part of the commit).
5. Documentation of the guarantee's exact scope: same inputs + same ilvuno + git + OS family.
6. Test: same spec built twice, 2 s apart, produces the same SHA; a changed version string in the
   binary does *not* change the SHA.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | Two builds of the same candidate produce identical commit SHAs |
| AC-2 | Changing `ilvuno --version` output does not change the SHA (asserted) |
| AC-3 | Commit date equals the base commit's committer time (asserted byte-exact) |
| AC-4 | Author/committer identity is exactly `ilvuno <ilvuno@localhost>` |
| AC-5 | `meta` ref exists and contains versions; deleting it does not change the candidate SHA |
| AC-6 | Docs state the guarantee's scope and what breaks it (`--attribute-to`, version band) |

## Test commands
```
go test ./internal/engine/ -run TestEnvelope -count=1 -v
go test ./internal/engine/ -run TestDeterminism -count=1 -v
```

## Evidence requirements
Two SHAs (identical), `git cat-file -p <sha>` showing the fixed envelope, `meta` ref content.

## Review checklist
- Is any wall-clock value used anywhere in a commit?
- Does the envelope leak into non-commit git calls (it must not)?
- Does the docs page say clearly what is *not* guaranteed (cross-git-version)?
