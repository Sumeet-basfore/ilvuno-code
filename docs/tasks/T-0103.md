# T-0103 — Config load/validate (`ilvuno.toml`)

Milestone: M1 · Estimate: 1 d · Owner: B · Provisional: no

## Goal
Parse the committed configuration strictly, with fail-closed defaults, so that a typo can never
silently change what runs.

## Dependencies
T-0101. Architecture `07` §10 (schema), `09` §4.1 (denied env), ADR-0014.

## Allowed file scope
- `internal/config/**`
- `schemas/config.schema.json` (or generated equivalent)
- `docs/ilvuno.toml.example`

**May not touch:** `internal/verify` (consumes config), `internal/cli`.

## Implementation outline
1. Strict TOML decode with unknown-key rejection at every level.
2. `CommandSpec` validation: name unique + `[a-z0-9-]+`, `run` non-empty, `timeout` parseable,
   `required` defaults **true**, `cwd` repo-relative and not escaping (`..` rejected at load),
   `env_allow` names checked against the denied-name list (denied wins → refuse with the variable name),
   `redact` regexes compiled at load.
3. Defaults: `runs=1`, `total_timeout=3600s`, `max_sources=16`, `max_candidate_files=100000`,
   `drift_threshold=50`, `repair.budget=2` (max 5), `hunk_proximity=false`.
4. `Digest()` over the canonical serialization, used by `--accept-config` and by the integrate cache
   key.
5. Zero-command config loads successfully (it is legal) but exposes `HasVerification()=false` so
   callers can force the `unverified` path.
6. Errors name the file, line, key, and the fix.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | Unknown key at top level or in any table is rejected with the key path |
| AC-2 | `env_allow = ["ANTHROPIC_API_KEY"]` is refused, naming the variable |
| AC-3 | `cwd = "../.."` is refused at load, not at spawn |
| AC-4 | `required` omitted ⇒ true (test asserts it) |
| AC-5 | `budget = 6` is refused with the max stated |
| AC-6 | `Digest()` is identical for two semantically identical files with different whitespace/ordering |
| AC-7 | Zero commands loads and reports `HasVerification()=false` |

## Test commands
```
go test ./internal/config/... -count=1 -v
```

## Evidence requirements
Table: input → error code / accepted. Digest stability test output.

## Review checklist
- Is anything defaulting to *permissive*? (should all default to conservative)
- Are regexes compiled once, and is a bad regex a load error rather than a runtime panic?
- Does the digest include the parts that affect behaviour and exclude comments?
