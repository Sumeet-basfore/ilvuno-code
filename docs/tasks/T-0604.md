# T-0604 — `explain`, `stats`, `brief`

Milestone: M6 · Estimate: 1.5 d · Owner: B · Provisional: no

## Goal
Three small commands that make the product trustworthy and shareable: why a finding fired, the user's
own numbers, and the concurrent-change brief that other agents can consume.

## Dependencies
T-0305 (report/findings), T-0403 (combination-only). `INT-260`, `INT-206`, architecture `12` §5–§7.

## Allowed file scope
- `internal/cli/explain.go`, `internal/cli/stats.go`, `internal/cli/brief.go`
- `internal/explain/**`, `internal/stats/**`
- `docs/metrics.md` (local metrics definitions)

**May not touch:** any network call; no telemetry.

## Implementation outline
1. `explain <run|finding>`: rule id, inputs (SHAs/paths/command), compared values, evidence refs, and
   "would change if" — all from stored records, no recomputation.
2. `stats`: read journals + metrics.jsonl; render runs, multi/single-source split, `combination_only`
   rate with counts, engine vs check time split, verdict distribution, `not_verified` count,
   repair outcomes. `--json`. No repo identifiers.
3. `metrics.jsonl` append on settle (local, prunable).
4. `brief`: deterministic Markdown export, ≤ token budget, files + overlaps + decisions + "do not"
   list; truncation marker with counts; no file bodies.
5. `brief --for-agent <name>` only adjusts wording/format, never content.
6. All three work offline and with the candidate worktrees deleted (journals + bundles only).

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | `explain` output is stable for the same records (golden test) |
| AC-2 | `explain` never recomputes a finding (asserted by removing the worktree and re-running) |
| AC-3 | `stats` shows `combination_only` rate with numerator and denominator visible |
| AC-4 | `stats` contains no repo name, path, or SHA |
| AC-5 | `brief` respects the token budget and marks truncation |
| AC-6 | `brief` contains no file contents and no model-generated text |
| AC-7 | All three work with the network disabled (asserted) |

## Test commands
```
go test ./internal/cli/ -run 'TestExplain|TestStats|TestBrief' -count=1 -v
make bench SCENARIO=B-22
```

## Evidence requirements
Golden explain output, a stats sample, a brief sample with the truncation marker, offline test log.

## Review checklist
- Does `stats` leak anything that identifies the repo?
- Is the `combination_only` denominator honest (multi-source runs with checks, not all runs)?
- Does `brief` read like instructions from another agent, or as data? (must be data)
- Is `explain`'s "would change if" accurate rather than aspirational?
