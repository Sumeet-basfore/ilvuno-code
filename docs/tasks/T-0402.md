# T-0402 — Five-state outcome, command evidence, exit codes

Milestone: M4 · Estimate: 1.5 d · Owner: A · Provisional: no

## Goal
Make the verdict honest and machine-checkable: exactly five outcomes, every skip explained, every
claim bound to a SHA, and exit codes that scripts can rely on.

## Dependencies
T-0401, T-0304, T-0305 (report sections). `VER-102`, `INT-303`, `INT-304`, `INT-310`, `EVD-107`.

## Allowed file scope
- `internal/verify/outcome.go`, `internal/verify/evidence.go`
- `internal/report/verification.go`
- `internal/cli/exit.go`
- `docs/exit-codes.md`, `docs/verification.md` (non-claim section)

**May not touch:** `internal/engine` state machine (consumes the outcome).

## Implementation outline
1. Outcome computation from command results: `passed | failed | unverified | inconclusive | error`,
   with the precedence rules (error > inconclusive > failed > unverified > passed).
2. Per-command `CommandResult` evidence record with argv, cwd, exit, signal, duration, blob refs,
   digest, advisory flag, skip reason.
3. `not_verified[]` builder: every configured-but-not-run command with a reason; plus
   `no_checks_configured` and `interface_analysis_skipped` (from M3).
4. Exit-code mapping in one table, tested as a matrix; no other code sets an exit code.
5. Confidence block: `high | low` + the reason (`no_checks_configured`, `inconclusive`, …).
6. Report section renderer for verification (matrix table + not_verified + confidence).
7. Documentation: the non-claim paragraph (runs project code as you, no sandbox) linked from the
   report footer.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | Five outcomes reachable; each has a fixture and an exit code; no sixth state exists in the enum |
| AC-2 | `B-15` → `unverified`, exit 4, confidence `low`, confidence reason present |
| AC-3 | A skip without a reason is a validation error (not an empty string) |
| AC-4 | Advisory failure does not change the outcome but is visible in the section |
| AC-5 | Every `passed` evidence record has a candidate SHA and a command result (`C-7`) |
| AC-6 | The full exit-code matrix test covers every documented code |
| AC-7 | Report footer contains the non-claim sentence and it is not removable by config |

## Evidence requirements
Outcome matrix table, exit-code matrix log, a rendered verification section with `not_verified`.

## Review checklist
- Can `passed` be produced with a skipped required command? (must be impossible)
- Is `inconclusive` used for "did not run" rather than `failed`?
- Does the confidence block ever say `high` when a check was skipped?
