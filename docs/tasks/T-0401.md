# T-0401 — Verification runner, supervision, env allowlist

Milestone: M4 · Estimate: 2 d · Owner: B · Provisional: no

## Goal
Execute the project's declared checks on a candidate, under supervision that cannot leak secrets or
leave orphans, and capture the raw material of evidence.

## Dependencies
T-0304 (evidence API), T-0205 (candidate). ADR-0008, `INT-301`..`INT-305`, architecture `07` §3–§4.

## Allowed file scope
- `internal/verify/runner.go`, `internal/verify/env.go`, `internal/verify/exec_unix.go`
- `internal/proc/**`
- `docs/verification.md` (the non-claim section is T-0402's, but the runner describes behaviour)

**May not touch:** `internal/engine` (calls in), `internal/report` (T-0402 adds sections).

## Implementation outline
1. `Run(ctx, pipeline, candidateWorktree)` sequential by default; `parallel_group` parsed but executed
   sequentially in v0.1 (documented).
2. Spawn `sh -c <run>` with `Setpgid`, cwd validated inside the worktree (`INV-12`), stdin `/dev/null`,
   stdout/stderr to per-command temp files (cap 64 MiB, truncate+flag).
3. Env: fixed allowlist + spec additions; denied-name list checked first; `TERM=dumb`, `CI=true`,
   `ILVUNO_*` set; `EnvFingerprint{names, hash}` stored, never values.
4. Timeout: `spec.timeout` → SIGTERM group → 5 s → SIGKILL group; record which rung fired.
5. Post-run orphan scan: children of the pgid; kill and record `orphan_killed`.
6. `tree_before/after` and `HEAD` captured around the whole pipeline (roll-up used by T-0404).
7. Streaming progress to stderr; no TTY required.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | A hung command is killed with TERM then KILL; no surviving children (pgid scan) |
| AC-2 | A command writing 1 GiB to stdout is capped, flagged `truncated`, run continues |
| AC-3 | Ambient `*_TOKEN`/`*_KEY` absent from the child; asserted by a command that dumps its env |
| AC-4 | `env_allow = ["GITHUB_TOKEN"]` is refused at load (config layer) and never passes through |
| AC-5 | `cwd` escaping the worktree is refused before spawn (`write_outside_scope`) |
| AC-6 | Commands run sequentially; progress is one line each; `TERM=dumb` works |
| AC-7 | A command that cannot be spawned yields a typed error, not a panic |

## Test commands
```
go test ./internal/verify/ -run 'TestRunner|TestEnv|TestTimeout|TestOrphans' -count=1 -v
make bench SCENARIO=B-12
```

## Evidence requirements
Timeout transcript (TERM→KILL rungs), env-dump child output showing no secrets, orphan scan result.

## Review checklist
- Is the process group always created (no path spawns without it)?
- Does the env allowlist ever pass the whole parent env by accident?
- Is output written to disk before redaction, or after? (must be after)
- Does the runner trust the command's exit code for anything other than "did it exit 0"?
