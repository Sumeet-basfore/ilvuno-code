# T-0003 — Failure-class fixture corpus

Milestone: M0 · Estimate: 1.5 d · Owner: B · Provisional: no

## Goal
The nine failure classes from `architecture/11` §3 exist as forge specs with asserted shapes, so
every later milestone can point at a named fixture instead of inventing one.

## Dependencies
T-0002. Architecture `11` §3, `05` §2.

## Allowed file scope
- `internal/testkit/fixtures/**`
- `docs/architecture/11-testing.md` (only if a fixture class needs clarification; amendment noted)

**May not touch:** production packages, forge internals (report a forge bug instead).

## Implementation outline
1. One file per class: `conflict_pair.go`, `conflict_triple.go`, `conflict_rename.go`,
   `api_incompatible.go`, `dependency_disagreement.go`, `lockfile_churn.go`, `stale_base.go`,
   `no_checks.go`, `unauthorized_ops.go`.
2. Each exposes `Spec() forge.Spec` + `Assert(t, repo)` verifying its shape (conflict presence,
   per-branch green/red, file counts).
3. `api_incompatible`: both branches compile alone; together they do not (a real, minimal TS-free
   analogue — use a tiny Go fixture module to keep the corpus dependency-free and fast).
4. `stale_base`: base advances after branch creation, so drift is measurable.
5. `unauthorized_ops`: a config with `cwd="../../"` and a journal template pointing at a user ref.
6. `corpus_test.go`: table over all nine, each runs `Assert` and a forge self-check.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | All nine classes exist and are named after their failure class |
| AC-2 | `api_incompatible` is green per branch and red in combination (asserted by a real command) |
| AC-3 | `conflict_triple` has all three pairs clean and the tuple conflicting (asserted) |
| AC-4 | `stale_base` reports a measurable drift count |
| AC-5 | Every fixture builds in < 400 ms |
| AC-6 | Fixtures contain no TypeScript/npm/network dependency (Go module only) |

## Test commands
```
go test ./internal/testkit/fixtures/... -count=1 -v
```

## Evidence requirements
Output table: fixture → class → asserted shape → build time.

## Review checklist
- Does the fixture *represent* the class, or merely resemble it? (the point of a corpus)
- Is `api_incompatible` failing for the right reason (compile error naming the renamed symbol)?
- Are fixtures minimal? (a 3-file fixture beats a 40-file one)
- No fixture asserts on human-readable git output (use `--porcelain`/`-z`).
