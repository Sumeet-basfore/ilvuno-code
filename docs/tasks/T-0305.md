# T-0305 — Report renderer, banned claims, bench harness

Milestone: M3 · Estimate: 2 d · Owner: A · Provisional: no

## Goal
The artifact a reviewer reads: ten fixed sections, stable/volatile split, banned-phrase enforcement,
plus the benchmark harness that makes regressions visible.

## Dependencies
T-0301, T-0304. `INT-605`, `VER-101`, architecture `12` §4, `planning/04-benchmarks.md`.

## Allowed file scope
- `internal/report/**` (renderer, templates, string table)
- `internal/report/banned_test.go`
- `internal/bench/**`
- `docs/report-format.md`

**May not touch:** `internal/verify` (M4 adds verification sections via a defined input struct).

## Implementation outline
1. `Report` input struct → Markdown and JSON renderers; sections: verdict, inputs, order, findings,
   steps, verification (empty stub in M3), combination-only (stub), repair (stub), evidence, next.
2. Stable/volatile split: `run{timestamps,durations,host}` vs the rest; `Normalize()` for comparison.
3. String table for every user-facing sentence; banned-phrase test scans the table (PRD Appendix A).
4. Next-actions derivation (deterministic, ≤5) from findings + state.
5. Footer line: what this proves / does not prove (fixed text, from the banned-safe table).
6. Bench harness: `make bench`, per-scenario runner, `bench.json`, gate evaluation, baseline file,
   `bench-update-baseline` requiring a review note.
7. Golden-file test for the report on 4 fixtures (normalized).

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | Normalized report is byte-identical across two runs with the same inputs |
| AC-2 | Adding "ready to merge" to the string table fails `make lint` |
| AC-3 | Interpretation content can be stripped and the report remains schema-valid |
| AC-4 | Every section present even when empty (`not_verified: none`) |
| AC-5 | `make bench` runs 24 scenarios, writes `bench.json`, returns non-zero on a gate failure |
| AC-6 | Golden files differ only in the `run` block across machines |
| AC-7 | Reading the report takes ≤ 60 s for a 3-source failure (outside reader, timed) |

## Test commands
```
go test ./internal/report/... -count=1 -v
make lint
make bench
```

## Evidence requirements
Two normalized report hashes, golden diffs, bench.json, the timed outside-reader note.

## Review checklist
- Does any sentence overclaim (verdict wording is the highest-risk text in the product)?
- Is `combination_only: unknown` rendered as unknown, not as false?
- Are the ten sections in fixed order?
- Does the harness ever pass by loosening a threshold?
