# T-0205 — Candidate construction + `integrate --dry-run`

Milestone: M2 · Estimate: 2 d · Owner: A · Provisional: no

## Goal
Turn N pinned SHAs into one deterministic candidate commit, attributable per step, with conflict
handling and partial integration — and expose it without verification yet.

## Dependencies
T-0201, T-0202, T-0203, T-0204. ADR-0006, `INT-105`..`INT-111`.

## Allowed file scope
- `internal/engine/candidate.go`, `internal/engine/integrate.go`
- `internal/cli/integrate.go` (dry-run only; full surface in T-0605)
- `internal/model/{candidate,integration_run}.go`

**May not touch:** `internal/verify` (M4), `internal/passport` (M6).

## Implementation outline
1. `Integrate(spec)`: fetch → pin → preflight → worktree → merge loop → `meta` ref → settle.
2. Merge loop: per source, journal intent, `git merge --no-ff --no-edit -m <msg> <sha>`, journal result;
   on conflict: `merge --abort`, record paths, then stop or skip per policy.
3. `--continue-on-conflict` semantics: skip the source, add to `excluded[]` with reason, continue.
4. Candidate record: ref, sha, tree, parents, included/excluded, created_at (deterministic).
5. `--dry-run`: pin + preflight + print the intended order and step list; no worktree, no refs.
6. Settle: cleanup (unless `--keep-worktree`), journal `run.settled`, return the run with `exit_code`.
7. Wire the `integrate` cache key (SHA set + config digest + versions) as a stub returning a miss in
   M2; the real cache lands in T-0502.

## Acceptance criteria
| AC | Statement |
|---|---|
| AC-1 | Two runs a week apart produce the same candidate SHA |
| AC-2 | Each step is a merge commit with the source SHA in the subject; step order matches the journal |
| AC-3 | A conflict at step 2 with `stop` leaves the tree clean, records steps 1–2, exit 3 |
| AC-4 | `--continue-on-conflict` produces a candidate from the survivors, with `excluded[]` reasons |
| AC-5 | `--dry-run` creates no worktree and no ref (fingerprint + ref diff) |
| AC-6 | Safety fingerprint unchanged on success, conflict, and SIGKILL |
| AC-7 | Only `refs/ilvuno/*` written; base ref untouched |
| AC-8 | `--keep-worktree` is the only way a worktree survives a settled run |

## Test commands
```
go test ./internal/engine/ -run 'TestCandidate|TestIntegrate' -count=1 -v
make bench SCENARIO=B-01; make bench SCENARIO=B-04
```

## Evidence requirements
Two identical SHAs across runs; `git log --graph` of a 3-source candidate; conflict transcript;
ref diff showing only `refs/ilvuno/*`.

## Review checklist
- Is the merge order recorded *before* the first merge?
- Does any path merge a ref instead of a SHA?
- Is `merge --abort` guaranteed on every conflict exit path (including error)?
- Does cleanup ever delete a ref it did not create?
