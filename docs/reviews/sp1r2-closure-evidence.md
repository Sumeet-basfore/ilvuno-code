**Scope:** harness-only remediation of the SP-1R closure audit
(`docs/reviews/sp1r-closure-audit.md`, findings A-1…A-9). No production code, M0 start,

## 1. Disposition of A-1 … A-9

| ID | Finding | Disposition | Evidence |
|---|---|---|---|
| **A-1** | `run-existing` sourced repository metadata as shell and accepted arbitrary repositories | **Closed.** Command removed. Manifest is parsed as strict `KEY=VALUE` data with an allowlist, full-OID validation, duplicate/missing/extra rejection. Pipelines refuse repositories not registered by this invocation. | M0–M3; §3 |
| **A-2** | Fixed `refs/ilvuno/candidates/r` / `meta/r` could overwrite and delete pre-existing refs; fingerprint excluded `refs/ilvuno/*` | **Closed.** Refs are `refs/ilvuno/runs/<run-id>/{candidate,meta}` with a 128-bit random run id. Creation is create-only (`update-ref … ""`), deletion requires the expected SHA, and the fingerprint includes all pre-existing refs including `refs/ilvuno/*`. | R1, R1b, R1c, R2; §4 |
| **A-3** | F10 content manifest used line-oriented output; the newline path got an empty-blob fallback hash | **Closed.** `content_manifest` parses `ls-tree -rz` and hashes blob bytes; any non-blob entry is recorded as `object:<oid>`, and any missing object fails. F10 now records hash `2d27fbdf…`, which matches the audit's independent value. | C-4, C-5; §5 |
| **A-4** | A supplied scratch root was treated as disposable; predictable paths could delete unrelated files | **Closed.** A supplied `SP1_SCRATCH` is a **parent**: a new exclusive `run-<32 hex>` child is created with `mkdir` (fails if it exists) and an `O_EXCL` ownership marker. Parent contents are never read as scratch or deleted. Only the run-owned child can be deleted. | P0.4, P0.8, P0.8b; §4 |
| **A-5** | `expected.py --update` accepted malformed input and derived expectations from the tested pipeline | **Closed.** Expectations are built from `spec.json` (hand-declared verdict/exit/cleanup) plus `oracle.json` (independent Git-native merges). Update refuses malformed JSON, missing/extra cases, count ≠ 28, duplicate keys, and any disagreement with the oracle. | P1.1, P1.2, P1.2b, E1–E11; §6 |
| **A-6** | `git_version` was required but not compared; policy/metadata not enforced | **Closed.** `git_version` must be in the environment profile's allowed set (2.55.0, 2.38.1); `os`, `merge_policy` and `metadata` are compared field-by-field. Any unsupported version fails. | E9, E10, E11; §6 |
| **A-7** | `safe_rmrf` validation and deletion are not atomic; some paths bypassed it | **Closed for M0 under the documented threat model; explicitly not hostile-filesystem safe.** All harness deletions route through `safe_rmrf`; the check/use window is documented and excluded by the "one process per fresh private root, no concurrent same-UID adversary" condition. Production cleanup remains an M2 gate. | P0.2, P0.3, §2, §6 |
| **A-8** | P0.6 did not invoke the harness; SG-4 did not pin the amended commit | **Closed.** P0.6 runs the harness with `SP1_VER=../../victim` and asserts the sentinel. SG-4 pins the commit that adds `.gitattributes`, asserts the refusal and the pinned SHA, and has a mutant that must fail. | P0.6, P0.6b, P0.6m, SG-4, SG-4c, SG-4m |
| **A-9** | "30 cases" in older reports and README; no cardinality check | **Closed.** All artifacts say **28**; `spec.json` declares `declared_case_count: 28` and update/check enforce it. | §6, `spec.json` |

No finding is left unaddressed. A-7 is the only one closed by an explicit threat-model restriction
rather than a code guarantee, exactly as the audit permits for M0.

Test groups (68 total): path/scratch 12, manifest 10, security gates 21, content/paths 2,
refs 4, repeat 3, matrix enforcement 5, expectation mutations 11.

**Limitations.**

1. The TOCTOU window in `safe_rmrf` remains; M0 relies on one process per fresh private root
   with no concurrent same-UID adversary. Not hostile-filesystem safe.
2. `spec.json` is hand-declared; it encodes expected behaviour, not proof that the behaviour is
   desirable. Review of that file is the control.
3. Non-UTF-8 paths use Python surrogate escapes in JSON; consumers that require strict UTF-8
   must handle them explicitly (bytes round-trip losslessly in the harness).
4. Two Git versions and Linux only. No macOS/Windows.
5. `harness_refused` rows are recorded with empty candidate/tree; the oracle intentionally does
   not model them (spec declares `candidate_from: none`).

## 8. Remaining M2 production blockers

The harness is not a production engine and this audit does not approve one:

- Hook, filter, custom merge-driver, attribute and submodule policy across every merge step.
- Run-owned ref names, scratch layout, cleanup ownership, and crash recovery in the product.
- Containment (OS-level) before executing arbitrary project verification commands.
- Concurrency model and lock semantics for multiple runs.
- Supported Git/OS matrix beyond 2.38.1/2.55.0 on Linux.
- Attestation of the Git floor image if it becomes release evidence.
- Strict JSON handling for non-UTF-8 path bytes in downstream consumers.
- Edge corpus: LFS, shallow/alternate repositories, case-only renames, metadata variation.
