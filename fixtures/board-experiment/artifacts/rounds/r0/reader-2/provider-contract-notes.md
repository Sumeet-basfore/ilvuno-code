# Provider contract: plain-language summary

- **Two adapters in v1.** `claude` talks the native stream-json and control protocol. `acp` uses the Agent Client Protocol and can point at any agent's ACP command. Both were proven in `research/09-spike.md`.
- **Zero first-party privilege.** Anything `claude` needs must also be available to the ACP adapter, or it is not part of the design.
- **The adapter only translates.** It never writes to the database, never decides a round is finished, and never retries a turn on its own. If it cannot answer a question, it reports `unknown` and the runner decides.
- **Commands go from runner to adapter.** They include spawn, session open and resume, prompt, permission reply, interrupt, park and unpark, and shutdown. Every command carries a `request_id`, so re-sending the same id must not start a second turn.
- **Eleven event kinds come back.** They cover spawn, session, text and thinking deltas, tool calls and results, permission requests, usage, turn finished, session ended, and `raw`. `raw` keeps any provider payload the contract does not model yet, so no information is lost.
- **Capabilities are declared, not probed.** The runner greys out features an adapter lacks and never fakes them. The list covers resume, fork, rewind, interrupt, steer, approvals, structured output, usage, and models.
- **Permissions work differently per wire, but map to one event.** For `claude`, the client must send an `initialize` handshake first, or every tool is silently denied. For ACP, the client picks an option by its kind (`allow_once` before `allow_always`), never by position. ACP also needs `"mode": "workspace-write"`, because the default mode hides permission requests from the runner. `/tmp` is writable in that mode, so it is not a boundary.
- **Prompts are part of the contract.** The worker and orchestrator texts ship with the runner, are versioned in code, and are injected on every turn. The worker must log intent before touching a file, stay inside its own folder, never switch branches or merge, ask when it needs a decision, and report exactly once. The orchestrator plans and delegates but does not write the deliverable.
- **Access rules.** A thread can write only inside its own folder. It can read its own folder, the run folder, and any absolute path in its task scope. Commands are injected with an absolute path to the runner binary.
- **Error classes have set responses.** Spawn failure marks the instance unavailable. Auth failure and usage limits pause the run and tell the human. A turn failure gets one retry. A protocol error marks the session broken. Unknown outcomes are recorded and never silently resent. An adapter crash counts as a turn failure and never takes down the runner.
