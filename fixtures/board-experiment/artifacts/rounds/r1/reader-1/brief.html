Brief: Ilvuno security model and provider contract

Security model

Ilvuno does not sandbox its agents. They run with the permissions the user already gave their CLI and with the vendor's own sandbox, so Ilvuno's job is to avoid giving them more access. The scope is a single user on a local machine. The repository is treated as untrusted, because instructions hidden in files can lead an agent to read files or run commands. Prompt injection is rated as a high residual risk.

The runner enforces a few things. Credentials stay out of agent environments. Each worker has its own worktree and cannot switch branches or touch main. Merges happen only in the runner after an accepted round. Diffs outside the declared scope are flagged, but not blocked. Every command and effect is journaled with a request id.

Known limits: there is no network allowlist, so an injected agent with shell access could send files out. Ilvuno cannot stop a determined injection, does not protect a machine that is already root-compromised, and does not protect against a malicious provider CLI. Defaults are conservative: approvals stay on, messaging is round-based, a human gate sits on every round, and the budget is 3 rounds or 150k tokens. Telemetry is off.

If an incident happens, freeze the run to park threads while keeping worktrees, read the journal, and do not rely on the runner to delete branches. If credentials may have leaked, rotate them at the provider, because Ilvuno never stores them.

Provider contract

Version 1 has two adapters. claude speaks the native stream-json and control protocol. acp speaks the Agent Client Protocol and can point at any agent's ACP command. The design gives no first-party privilege: anything claude needs must also be available through ACP.

The adapter only translates. It never writes to the database, never decides that a round is finished, and never retries a turn on its own. If it cannot answer a question, it reports unknown and the runner decides. Commands flow from runner to adapter and carry a request_id, so resending the same id must not start a second turn. Eleven event kinds flow back, and raw keeps any provider payload the contract does not yet model.

Capabilities are declared, not probed. The runner greys out features an adapter lacks and never fakes them. Permissions differ by wire but map to one event. claude needs an initialize handshake first, or every tool is silently denied. ACP picks an option by its kind, never by position, and needs "mode": "workspace-write". /tmp is writable in that mode, so it is not a boundary.

Prompts are part of the contract. The worker and orchestrator prompts ship with the runner and are injected on every turn. Workers log intent before touching a file, stay in their own folder, never switch branches or merge, ask when they need a decision, and report once. The orchestrator plans and delegates but does not write the deliverable.

Access rules: a thread writes only inside its own folder and reads its own folder, the run folder, and any absolute path in its task scope. Error classes have fixed responses. A spawn failure marks the instance unavailable. Auth failures and usage limits pause the run and tell the human. A turn failure gets one retry. A protocol error marks the session broken. Unknown outcomes are recorded and never silently resent. An adapter crash counts as a turn failure and never takes down the runner.
